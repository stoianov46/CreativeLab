# Безопасность токенов — CreativeLAB

## ❗ Железное правило

**В коде не должно быть ни токенов, ни паролей.**

Всё — через переменные окружения:

- Локально — `.env.local` (шаблон: `.env.example`); на хостинге — env vars платформы
- `.env*` в `.gitignore` (кроме `.env.example`, в нём только пустые имена переменных)
- Секреты — **никогда** не в `src/` и **никогда** в `NEXT_PUBLIC_*` (такие переменные вшиваются в клиентский JS и видны любому посетителю)
- Клиент → серверный API route → внешний сервис (токен живёт только на сервере)

## Где используются

| Переменная | Где читается | Назначение |
|-----|-------|--------|
| `TELEGRAM_BOT_TOKEN` | `src/app/api/contact/route.ts`, `bots/shared/notify.ts` | Бот, который шлёт лиды в staff-чат |
| `TELEGRAM_STAFF_CHAT_ID` | там же | ID staff-чата |

## Если токен утёк

1. Отозвать/перевыпустить токен сразу (для Telegram — @BotFather → `/revoke`)
2. Положить новый только в env vars (локально и на хостинге)
3. Удаление из кода не отменяет утечку: старый токен остаётся в истории git и в уже задеплоенных бандлах — поэтому шаг 1 обязателен
